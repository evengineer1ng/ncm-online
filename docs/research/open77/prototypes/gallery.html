Everything below is CSS geometry and inline SVG over the proposed ncm-ui.css token layer. No network, no webfont, no image file — so this is what an in-game CEF surface can actually render. The point is not the styling of any one component; it is that one token contract produces all of them.

Tyres

A delta is the one figure NCM shows whose sign is the meaning, so it gets its own ahead/behind pair rather than reusing ok/danger — otherwise every slower lap reads as an error. A personal best gets a third colour because it is a different kind of event. Tyre state is a four-step ramp (cold / ready / hot / spent), not good-versus-bad, because wear is a continuum and the Wear system already models it that way. Figures are tabular-nums so they stop jittering.

8 · Motion, on the platform's own timings

slide 220ms

pulse · live

Durations and easing are tokens, not numbers: 90ms for colour and border, 150ms for enter and leave, 220ms for a whole panel, on cubic-bezier(0.2,0,0,1). The platform's stated rule is inherited with them — functional and fast; no glitch loops, no parallax, no idle animation — as is the prefers-reduced-motion block, which NCM honours nowhere today because it ships no copy of the token file. NCM has zero @keyframes at present; the platform proves 38 of them in-engine.

9 · What this prototype proves, and what it does not

Proven hereStill unproven
One token contract renders every component aboveHow any of it looks on a real CEF surface over moving gameplay
All marks are CSS or inline SVG — no asset delivery neededFrame cost with several components animating at once
The glyph set already covers race, event, route and weather statesThat Bahnschrift Condensed is what the client actually picks
Type stays at or above the 9px HUD floor throughoutLegibility at speed, which needs a driver, not a reviewer
Colour is never the only carrier of meaningUltrawide behaviour: this page is fluid, NCM's pages are fixed 1920×1080

The three existing harnesses (tools/{panel,race,nameplate}-render-check.js) stub a DOM in Node and assert that a render did not throw. They prove logic, not appearance — so in-engine visual and cost verification remains the first owed step, and nothing above should be read as a live PASS.
