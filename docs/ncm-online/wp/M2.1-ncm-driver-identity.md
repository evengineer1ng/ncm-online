# WP M2.1 — Become an NCM driver

Milestone: M2 (world layer). Status: **COMPLETE 2026-09-19** (reconnect showed the same id with `(persisted)`). Depends on M0.1/M0.2.

## What it does
On join, `ncm_world` holds readiness, looks up `(serverId, userId)` in `ncm_driver_binding`; when absent it mints an NCM Driver ID (core `competition.driver.mint`, uuid v4 from host randomness), writes `ncm_driver` + binding + `driver_profile` in one transaction, publishes a public view on the player's state bag (`ncm` key), releases the hold, and on ready sends a toast + chat line. `/ncm` prints the driver. `serverId` is an operator tunable (default `ncm-dev`).

## Lessons (platform)
- Manifest changes (scripts, permissions, dependencies) need a **full server restart**; `restart <resource>` re-runs the old script list.
- A server-only resource must not be named in `dependency` by a resource that has a client half: the client cannot satisfy it → `resource_activation_failed`. Order via readiness polling instead.
- State-bag writes are gated by `network.events` on .78/.82 (the guide's `state.write` name is not a real permission).
- `tools/ncm-build.ps1` now reads manifests as UTF-8 (it mangled a non-ASCII comment once).
