**This file is never pruned.** Every idea, feature, concern, fix and "wouldn't it be good if" goes in here the
moment it is spoken, with a permanent ID, whether or not it will ever be built (L68). Rows change *state*; they are
never deleted. Dropping an idea means setting its state to `dropped` with a reason, so the reasoning survives too.

Capturing is not committing. A `raw` row costs nothing and obliges nothing. The point is that a caffeinated human
and an agent with no memory can both come back in three weeks and find the thought intact.

**States:** `raw` (captured, no design) → `shaped` (there is a design or an owner answer) → `scheduled` (assigned to
a milestone or batch) → `built` (code + offline proof) → `validated` (live PASS logged) · `dropped (reason)` ·
`blocked (on what)`.

**Where things live:** ideas and work → here. Choices made and questions for the owner → `DECISION_RECORD.md`.
Defects → `KNOWN_BUGS.md`. Live PASS/FAIL → `wp/MASTER_TEST.md`. What to do next → `NOW.md`.

## How this file is organised (2026-09-24)

Three changes, no deletions. Every row, ID and word of every note is still here.

1. **Every row now carries a `Class`** — what *kind* of thing it is, which decides how expensive it is to get
   wrong later. This is a different axis from `State`, which says how far along it is.
2. **Completed rows moved to the bottom**, under their original section headings, in `## Completed`.
3. **The foundation register below** names what has to be right *before* production takes more data.

| Class | Meaning | Cost of changing it later |
|---|---|---|
| **F0** | Substrate that production **already stores**, or an owner decision gating it — identity, serialisation, provenance, immutable history | **Highest.** A migration at best; permanently lost history at worst |
| **F1** | Data model the vision depends on, **not yet written** — parts, components, engineering, wear | Free to design today. A migration the moment any production row exists |
| **INV** | An invariant: a rule that constrains the model rather than code that implements it | Cheap now, structural later — these decide what F1 is allowed to look like |
| **GATE** | A proof or audit that must pass before something can safely be built on top | Cheap. Skipping one is what makes the others expensive |
| **SYS** | System behaviour and logic | Low — changeable without migrating data |
| **UI** | Presentation, HUD, panels, content, ceremony | Lowest. Deferrable indefinitely |
| **OPS** | Tooling, process, docs, QA harness | Low |
| **UP** | Blocked on the platform / upstream ask | Not ours to schedule |
| **DSN** | Open product or design question with no data implication yet | Free |

`·LIVE` appended to a class means **production already holds rows in that shape**.

## ⚑ Foundation register — what must be right before production takes more data

The owner's framing, 2026-09-24: *"we can't slip up on things like serialized cars… those serializations need to
exist in their relative final form before touching production anymore… I'd rather be parked at the door for design
work later than find out after building on weak foundation."*

**The audit says that instinct is correct, and one item is already costing us.** 35 of the 163 open rows are
data-model or schema work; 28 are UI that can wait indefinitely. The split is real, not a feeling.

### P0 — decide or build before the next production race

- **IDEA-236** — F0 — **This one is actively losing history right now.** Production holds **29 completed results, none attributable to a machine.** `session_result` has no `asset_id` — and neither does `entry` or `seat`, so it is **not reconstructible**: the car fielded was never written down anywhere. Every race run from now adds another permanently anonymous result. It also blocks the Machine Profile (`IDEA-237`) and undercuts wear/engineering, which need to know *which machine* did the distance. Cheap to add, impossible to backfill.
- **IDEA-233** — F0 — Owner decision: do admin/progression grants carry serials? Until answered, the serial space has an undefined hole and every grant made meanwhile is a row that may need retrofitting.
- **IDEA-238** — F0 — Owner decision: are NCX team cars persistent assets? Today they are equipment with no `assetId`, so they cannot accrue odometer (`IDEA-232`) and cannot carry components. Answer changes the data model for team equipment.
- **IDEA-287** — GATE — Already promoted to prerequisite (L120): odometer integrity must be proven **before** distance carries economic weight. §AG5/§AG6 are still NOT RUN. Once distance is money, a measurement artifact becomes an exploit.
- **IDEA-249** — GATE — Engine-capability audit — *gates every component effect*. Building a parts model before knowing what vehicle behaviour can actually be manipulated risks a model describing things the engine cannot express.

### P1 — the parts/engineering/wear data model, while it is still free

Nothing here has a production row yet, which is exactly why now is the cheap moment. The spine, in dependency order:

- **IDEA-240** — Vehicle mechanical architecture profile — compatibility *derived*, not listed per model
- **IDEA-241** — Component **design** identity vs the manufactured component **asset** — the same offering/asset split already proven live by `IDEA-213`
- **IDEA-286** — The seven layers that must never merge on one component
- **IDEA-283** — Seeded lifecycle profile evaluated against accumulated exposure — no per-km rolls
- **IDEA-246** / **IDEA-247** — Parts ownable independently of vehicles; atomic heterogeneous barter (the largest new transaction architecture implied anywhere in this ledger)
- **IDEA-254** — Distribution relationships at four scopes — explicitly schema-shaping
- **IDEA-276** — Attributed operation history on component assets (the engineering biography)
- **IDEA-266** — Knowledge ladder, stored separately from bounded competency (L120)

The **14 INV rows** are not work — they are the rules that decide what the above is allowed to look like. They cost
nothing now and become structural once a table exists. Settle them alongside the model, not after it.

### Deliberately NOT gating anything

All 28 **UI** rows, and the presentation half of the parts specs (`IDEA-248` product cards, `IDEA-253` market
switching, `IDEA-277` roll ceremony, `IDEA-237` Machine Profile). They need the model; the model does not need them.

## How to use this file

- **Adding:** append a row with the next free ID, bump the "next free ID" line at the top, state `raw`. Do not
  stop to design it. One sentence is enough.
- **Promoting:** when an idea gets a design or an owner answer it becomes `shaped`; when it enters a batch or
  milestone it becomes `scheduled` and the "Lands in" column is filled.
- **Finishing:** `built` when code and offline proof exist; `validated` only when a live PASS is logged in
  `wp/MASTER_TEST.md`. `built` is not done (L69).
- **Dropping:** never delete. Set `dropped (reason)` so the next session does not rediscover and re-argue it.
